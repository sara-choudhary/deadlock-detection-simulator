How detection works

The server starts with Work equal to Available. A process that holds nothing starts as finished, because it cannot be blocking anyone. Then it repeats:

  1. Find the lowest-numbered unfinished process whose Request fits inside Work, resource by resource.
  2. If there is one, assume it runs to completion and returns what it holds: add its Allocation to Work.
  3. If there is none, stop. Every process still unfinished is reported as deadlocked.

Reading the result

No deadlock means there is an order in which every process can finish, using the resources released along the way. Deadlock detected means the listed processes can never get what they wait for, because it is held by processes that are themselves stuck. The answer describes only the numbers you entered. No real processes are inspected, and the order shown is one valid order, not a promise about every possible schedule.
